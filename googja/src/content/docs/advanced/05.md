## 1. バイブコーディングにおいて自動テストが「最高の安全装置」になる理由

AIエージェントは非常に優秀ですが、時に人間の予想を超えたコードの書き換えを行います。

リポジトリに自動テストが存在すると、AIとの協業スタイルは次のように劇的に進化します。

- **「テストが通るまで自分で直して」と指示できる**: ターミナルで `npm test` を実行させ、テストが失敗したらAI自身がスタックトレースを読み取って自律的に修正コードを書き直す（テスト駆動バイブコーディング）。
- **デグレの恐怖から解放される**: 既存のコア機能（習慣の追加やトグル計算など）が壊れていないことを数秒で機械的に検証できる。

## 2. Jestによるロジックの単体テストとReact Native Testing Library

まずはExpo推奨のテスト環境をセットアップします。

```bash
npx expo install jest-expo jest @types/jest
```

習慣データの計算ロジック（例: 連続達成日数のカウント）をテストするテストコードを作成します。

```typescript
// __tests__/habitLogic.test.ts
describe('Habit streak calculation', () => {
  it('前日に達成している場合、streakが1増えること', () => {
    const previousStreak = 5;
    const isCompletedYesterday = true;
    const currentStreak = isCompletedYesterday ? previousStreak + 1 : 1;

    expect(currentStreak).toBe(6);
  });

  it('2日以上途切れた場合、streakが1にリセットされること', () => {
    const isCompletedYesterday = false;
    const currentStreak = isCompletedYesterday ? 5 + 1 : 1;

    expect(currentStreak).toBe(1);
  });
});
```

ターミナルで `npm test` を実行し、全テストが緑色（PASS）で通過することを確認します。

## 3. GitHub Actionsによる自動チェック（型検査・Lint・テスト）の設定

GitHubにコードをプッシュしたり、Pull Requestを作ったりした際に、クラウド上で自動的にテストを走らせるワークフローを定義します。

`.github/workflows/ci.yml` を作成します。

```yaml
name: CI Quality Check

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Run TypeScript check
        run: npx tsc --noEmit

      - name: Run Jest tests
        run: npm test -- --ci
```

この設定により、型エラーやテストの失敗があるコードはGitHub上で警告が表示され、未完成なコードが誤って本番に混ざるのを防げます。

## 4. EAS CLIと連携したプルリクエスト自動ビルド

さらに進んだ設定として、GitHubのmainブランチにマージされた際、EAS Buildを自動トリガーしてFirebase App Distributionへ最新ビルドを自動配備する「完全自動デリバリー」も可能です。

EASのアクセストークン（`EXPO_TOKEN`）をGitHubのSecretsに登録し、以下のステップを追加します。

```yaml
      - name: Setup EAS
        uses: expo/expo-github-action@v8
        with:
          eas-version: latest
          token: ${{ secrets.EXPO_TOKEN }}

      - name: Build and Distribute
        if: github.ref == 'refs/heads/main'
        run: eas build --platform android --profile preview --non-interactive
```

これで、あなたがGitHubに `git push` するだけで、15分後にはテスターのスマホに最新アプリが自動配信される「夢の開発パイプライン」が完成します。

## 5. Sentryによる本番クラッシュ監視と継続的DevOpsサイクル

アプリをリリースした後は、ユーザーの手元で発生した予期せぬクラッシュをリアルタイムに検知する体制を作ります。

Expo公式対応の **Sentry (`sentry-expo`)** を導入すれば、クラッシュ時のスタックトレースや端末情報が即座にダッシュボードに通知され、そのログをAIエージェントに渡すだけで数分で原因究明と修正パッチの作成が完了します。

1. **仕様定義**: `SPEC.md` と `DESIGN.md` で迷いをなくす。
2. **高速実装**: AIエージェントと対話しながら実機プレビューで爆速開発。
3. **自動検証**: CI/CDと単体テストで品質を24時間監視。
4. **迅速配布**: Firebase App Distributionでユーザーの声を即座に回収。
5. **継続改善**: フィードバックとSentryのエラーログを次のリリースへ即座に反映。

個人であっても、AIと適切なツールチェーンを味方につければ、数人の開発チームに匹敵するスピードと品質でプロダクトを運営し続けることができます。
