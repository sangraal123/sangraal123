## 1. Google AdMob広告の組み込みとiOS ATT（追跡許可）対応

広告を導入する場合、以下の設定漏れがあると即座にApple審査でリジェクトされます。

:::caution[AdMobはExpo Goでは動きません]
AdMob（`react-native-google-mobile-ads`）はネイティブコードを含むため、**Expo Go では動作を確認できません**。開発ビルド（`eas build --profile development`）またはEAS Buildで作った実機ビルドで検証してください。同じことが RevenueCat の課金や、Expo Go 上でのリモートプッシュ通知にも当てはまります。
:::

### App Tracking Transparency (ATT) の対応
iOS 14.5以降、広告トラッキングを行う場合はユーザーに明示的な許諾ダイアログを表示する必要があります。

`app.json` に許可メッセージを定義します。

```json
{
  "expo": {
    "ios": {
      "infoPlist": {
        "NSUserTrackingUsageDescription": "適切な広告を表示し、無料でのアプリ提供を継続するために利用状況の収集を許可してください。"
      }
    }
  }
}
```

ダイアログはアプリ起動直後ではなく、最初の習慣を登録したタイミングなど、ユーザーがアプリの価値を少し理解した後に表示するのが承諾率を高めるコツです。

## 2. 課金機能の必須審査要件（復元ボタン・利用規約リンク）

アプリ内課金（広告削除やサブスクリプション）を導入する場合、Appleのガイドライン（Guideline 3.1.1）により、購入画面（ペイウォール）に以下の要素が**視覚的に明記されていること**が絶対条件です。

1. **購入の復元（Restore Purchases）ボタン**: 端末変更時や再インストール時に再課金させないためのボタン。タップ時に復元処理が走る必要があります。
2. **利用規約（Terms of Service / EULA）へのリンク**: タップすると規約ページが開くこと。
3. **プライバシーポリシー（Privacy Policy）へのリンク**: タップするとポリシーページが開くこと。
4. **サブスクリプション期間と価格**: （例: 「月額350円・いつでも解約可能」）

これらが欠けていると「100%リジェクト」されるため、購入コンポーネント内に必ず目立つ形で配置しておきます。

## 3. レビュアーに喜ばれる「審査用メモ」の書き方完全版

App Store Connect の審査提出画面には「App Reviewに関する情報（審査用メモ）」欄があります。

ここに親切な案内を英語で書いておくと、レビュアーが迷わずスムーズに承認してくれます。

```text
【審査用メモの記載テンプレート】
Dear App Review Team,

Thank you for taking the time to review HabitFlow.
- This app is an offline-first minimalist habit tracker designed with Expo.
- No login or personal information is required. All data is stored locally via AsyncStorage.
- To test the core features:
  1. Tap the '+' button at the bottom right to add a habit (e.g., "Reading").
  2. Tap the checkbox on the habit card to mark it as completed.
  3. Navigate to the History tab to review the streak calendar.
  4. Navigate to the Settings tab to test data reset.

If you have any questions or need further details, please reach out to:
Email: your-email@example.com
```

## 4. 審査提出とステータス推移（In Reviewの過ごし方）

すべての項目に緑のチェックがついたら、**「審査に追加」** → **「審査に提出」** をクリックします。

### ステータスの推移
1. **Waiting for Review（審査待ち）**: 通常数時間〜24時間程度。
2. **In Review（審査中）**: レビュアーが実際に操作中（1〜3時間程度）。
3. **Pending Developer Release（公開待ち）** または **Ready for Sale（販売中）**: **祝・合格！** ストアに並びます。

## 5. もしリジェクトされたら？AIを使った迅速な原因究明と異議申し立て英文テンプレート

もし「Guideline XX.X に抵触したため却下されました」という通知が届いても、落ち込む必要は全くありません。**リジェクトはアプリ開発の日常茶飯事**です。

レビュアーから送られてきたメッセージをそのままAIエージェントに貼り付けます。

```text
【プロンプト】
Appleの審査チームから以下のリジェクト理由が届きました。
ガイドラインの意図を解説し、現在のコードのどこを修正すれば合格できるか具体的なコード修正案を提示してください。
また、レビュアーへの丁寧な返信メッセージのドラフト（英語）を作成してください。

[レビュアーからのメッセージ本文]
```

### レビュアーへの返信英文テンプレート
```text
Dear App Review Team,

Thank you for your feedback regarding Guideline [ガイドライン番号].
We have updated the app in build [新しいビルド番号] to resolve this issue:
- [修正点1: e.g., Added a clear "Restore Purchases" button to the paywall view.]
- [修正点2: e.g., Updated privacy links in accordance with the guideline.]

Please review the updated build. Thank you for your support!
```

指摘された箇所をAIと一緒に数十分で直し、新しいビルド番号で再提出すれば、大半は次回ですんなり通過します。
