## 1. Google AdMob広告の組み込みとiOS ATT対応

広告を導入する場合、以下の設定漏れがあると即座にApple審査でリジェクトされます。

:::caution[AdMobはExpo Goでは動きません]
AdMob（`react-native-google-mobile-ads`）はネイティブコードを含むため、**Expo Go では動作を確認できません**。開発ビルド（`eas build --profile development`）またはEAS Buildで作った実機ビルドで検証してください。同じことが RevenueCat の課金や、Expo Go 上でのリモートプッシュ通知にも当てはまります。
:::

### App Tracking Transparency (ATT) の対応

iOS 14.5以降、広告トラッキングを行う場合はユーザーに明示的な許諾ダイアログを表示する必要があります。

`app.json` に許可メッセージを定義します。

```json
{
  "expo": {
    "ios": {
      "infoPlist": {
        "NSUserTrackingUsageDescription": "適切な広告を表示し、無料でのアプリ提供を継続するために利用状況の収集を許可してください。"
      }
    }
  }
}
```

ダイアログはアプリ起動直後ではなく、最初の習慣を登録したタイミングなど、ユーザーがアプリの価値を少し理解した後に表示するのが承諾率を高めるコツです。

:::tip[テスト広告の照合が効かなくなる落とし穴]
ATTのダイアログを**拒否すると、iOSのIDFAはオールゼロになります**。AdMobのテストデバイス登録をIDFAで行っている場合、拒否した瞬間に照合が壊れて**本番広告が配信されます**。しかも**iOSはインストールごとに1回しかダイアログを出さない**ので、一度誤って拒否すると入れ直すまで戻せません。

テスト端末では必ず「許可」してください。そして、**自分の広告は絶対にタップしないこと**。自己クリックは無効なトラフィックと判定され、AdMobアカウントの停止につながります。表示されるだけなら直ちに危険ではありませんが、タップは一発で問題になります。
:::

## 2. 自前実装ではなくRevenueCatを使う理由

アプリ開発者が夢見るゴールのひとつが、**毎月安定して発生するサブスクリプション収益**です。

しかし、iOSのStoreKitとAndroidのGoogle Play Billingは、仕様、レシート検証、解約・更新通知の処理がそれぞれ異なり、自前でサーバーを立てて連携するのは開発者にとって最大の悪夢でした。

AppleとGoogleの課金システムには、次のような無数の落とし穴があります。

- レシート（購入証明）の暗号署名検証をサーバーサイドで常に行う必要がある
- クレジットカード決済の失敗、猶予期間（Grace Period）、プラン変更（アップグレード / ダウングレード）の追跡
- ユーザーが別端末に乗り換えた時の「購入の復元」処理

その複雑さをすべて解決し、現在のモバイルアプリ開発でデファクトスタンダードとなっているのが **RevenueCat** です。これらのバックエンド処理、Webhook、レシート検証をすべてクラウド側で肩代わりしてくれます。個人開発者であれば**月間売上が約2,500ドル（約38万円）に達するまで完全無料**で利用できます。

:::note[買い切り1本だけなら、RevenueCatは無くても構いません]
RevenueCatの価値は**サブスクの状態管理**にあります。更新、猶予期間、支払いリトライ、プラン変更、プラットフォームをまたいだ権利の同期。これらは、**「広告非表示」の買い切り（非消耗型）1本には、ひとつも存在しません**。状態は「持っている / 持っていない」の2値だけで、`restorePurchases` が答えます。

しかもSDKを1つ足すと申告作業が増えます。iOSは `PrivacyInfo.xcprivacy` にサードパーティSDKの申告が要り、Playはデータセーフティ フォームに送信データの申告が要ります。

**買い切り1本から始めるなら `expo-in-app-purchases` 相当の素の実装で足り、後からサブスクを足す判断をした時点でRevenueCatに移行できます**。以下はサブスクまで見据える場合の手順です。
:::

## 3. ストア側の課金アイテム登録とEntitlement設計

### ストア管理画面でプロダクトを作る

まずは各ストア管理画面で課金プロダクトを作成します。

- **プロダクトIDの命名規則**: `com.yourname.app.premium.monthly` のように命名します。
- **タイプ**:
  - **自動更新サブスクリプション**: 例「HabitFlow Pro（月額350円 / 年額3,000円）」
  - **非消耗型アイテム（Non-Consumable）**: 例「広告非表示（買い切り500円）」

:::danger[プロダクトIDは、作成後に変更も再利用もできません]
打ち間違えても直せず、別のIDを作り直すことになります。そして**両ストアで同じIDに揃えておく**と、アプリ側の定数が1つで済みます。ここは最初に落ち着いて決めてください。
:::

前提として、Appleの**有料アプリ契約**とGoogleの**支払いプロファイル**が有効になっている必要があります。広告だけのアプリには不要だった手続きで、契約への同意、銀行口座の登録、税務情報の提出（日本の情報に加えて米国向けの申告フォーム）が含まれます。**本人確認に数日かかることがある**ので、実装より先に着手しておくのが得です。

### RevenueCatでEntitlement（権利）を設計する

RevenueCatでは、App StoreのプロダクトとGoogle Playのプロダクトを、1つの抽象的な**権利**（Entitlement）にまとめます。

- **Entitlement Identifier**: `pro`
- **Attached Products**:
  - Apple: `com.yourname.habitflow.pro.monthly`
  - Google: `habitflow_pro_monthly`

これにより、コード上では「このユーザーは `pro` を持っているか」だけを判定すればよく、OSの違いを意識する必要が一切なくなります。

## 4. RevenueCat SDKの導入とペイウォールの実装

### SDKの導入と初期化

Expoプロジェクトに RevenueCat のパッケージをインストールします。

```bash
npx expo install react-native-purchases
```

アプリの起動時（`app/_layout.tsx`）で初期化します。

```typescript
import { useEffect } from 'react';
import { Platform } from 'react-native';
import { Slot } from 'expo-router';
import Purchases, { LOG_LEVEL } from 'react-native-purchases';

const APIKeys = {
  apple: process.env.EXPO_PUBLIC_REVENUECAT_APPLE_KEY || '',
  google: process.env.EXPO_PUBLIC_REVENUECAT_GOOGLE_KEY || '',
};

export default function RootLayout() {
  useEffect(() => {
    Purchases.setLogLevel(LOG_LEVEL.DEBUG);

    if (Platform.OS === 'ios') {
      Purchases.configure({ apiKey: APIKeys.apple });
    } else if (Platform.OS === 'android') {
      Purchases.configure({ apiKey: APIKeys.google });
    }
  }, []);

  return <Slot />;
}
```

### ペイウォール（購入画面）を実装する

ユーザーにプレミアムプランを提示するモーダル画面を作成します。**次の節で解説する審査必須要素（復元ボタン・利用規約リンク・期間と価格の明示）を、最初から組み込んだ形**にしてあります。

```typescript
// components/PaywallModal.tsx
import React, { useEffect, useState } from 'react';
import { View, Text, TouchableOpacity, Alert, StyleSheet, Linking } from 'react-native';
import Purchases, { PurchasesPackage } from 'react-native-purchases';

export function PaywallModal({ onClose }: { onClose: () => void }) {
  const [loading, setLoading] = useState(false);
  const [packages, setPackages] = useState<PurchasesPackage[]>([]);

  useEffect(() => {
    Purchases.getOfferings()
      .then((offerings) => setPackages(offerings.current?.availablePackages ?? []))
      .catch(() => setPackages([]));
  }, []);

  const handlePurchase = async (pkg: PurchasesPackage) => {
    try {
      setLoading(true);
      const { customerInfo } = await Purchases.purchasePackage(pkg);
      if (customerInfo.entitlements.active['pro'] !== undefined) {
        Alert.alert('ありがとうございます！', 'プレミアム機能がアンロックされました。');
        onClose();
      }
    } catch (e: any) {
      if (!e.userCancelled) {
        Alert.alert('エラー', e.message);
      }
    } finally {
      setLoading(false);
    }
  };

  const handleRestore = async () => {
    try {
      const customerInfo = await Purchases.restorePurchases();
      if (customerInfo.entitlements.active['pro'] !== undefined) {
        Alert.alert('復元完了', '過去の購入履歴が復元されました。');
        onClose();
      } else {
        Alert.alert('お知らせ', '有効な購入履歴が見つかりませんでした。');
      }
    } catch (e: any) {
      Alert.alert('エラー', e.message);
    }
  };

  return (
    <View style={styles.container}>
      <Text style={styles.title}>HabitFlow Pro</Text>
      <Text style={styles.subtitle}>無制限の習慣登録とAIコーチによるアドバイス</Text>

      {/* 購入ボタン。offerings から取得した package を渡す */}
      {packages.map((pkg) => (
        <TouchableOpacity
          key={pkg.identifier}
          onPress={() => handlePurchase(pkg)}
          disabled={loading}
          style={[styles.buyBtn, loading && styles.buyBtnDisabled]}
          activeOpacity={0.7}
        >
          <Text style={styles.buyText}>
            {pkg.product.title}　{pkg.product.priceString}
          </Text>
        </TouchableOpacity>
      ))}

      {/* 審査に必須：期間と価格の明示 */}
      <Text style={styles.terms}>
        月額サブスクリプションです。期間終了時に自動更新され、いつでも解約できます。
      </Text>

      {/* 審査に必須の「購入の復元」ボタン */}
      <TouchableOpacity onPress={handleRestore} style={styles.restoreBtn}>
        <Text style={styles.restoreText}>以前の購入を復元する（Restore Purchases）</Text>
      </TouchableOpacity>

      {/* 審査に必須：利用規約とプライバシーポリシーへのリンク */}
      <View style={styles.linkRow}>
        <TouchableOpacity onPress={() => Linking.openURL('https://example.com/terms')}>
          <Text style={styles.linkText}>利用規約（EULA）</Text>
        </TouchableOpacity>
        <Text style={styles.linkSep}>・</Text>
        <TouchableOpacity onPress={() => Linking.openURL('https://example.com/privacy')}>
          <Text style={styles.linkText}>プライバシーポリシー</Text>
        </TouchableOpacity>
      </View>
    </View>
  );
}

const styles = StyleSheet.create({
  container: { padding: 24, alignItems: 'center' },
  title: { fontSize: 24, fontWeight: 'bold', color: '#111827' },
  subtitle: { marginTop: 8, color: '#6B7280', textAlign: 'center' },
  buyBtn: {
    marginTop: 24,
    paddingVertical: 14,
    paddingHorizontal: 32,
    borderRadius: 12,
    backgroundColor: '#10B981',
  },
  buyBtnDisabled: { opacity: 0.5 },
  buyText: { color: '#FFFFFF', fontSize: 16, fontWeight: '600' },
  terms: { marginTop: 12, fontSize: 12, color: '#6B7280', textAlign: 'center' },
  restoreBtn: { marginTop: 20 },
  restoreText: { color: '#10B981', textDecorationLine: 'underline', fontSize: 13 },
  linkRow: { flexDirection: 'row', marginTop: 16, alignItems: 'center' },
  linkSep: { marginHorizontal: 6, color: '#6B7280' },
  linkText: { color: '#6B7280', textDecorationLine: 'underline', fontSize: 12 },
});
```

:::tip[価格は必ずストアが返す文字列を表示する]
`¥500` のような文字列をコードに焼き込まないでください。ユーザーのストアフロントが日本以外だと**表示が嘘になります**。上のコードのように `pkg.product.priceString` をそのまま出すのが正解です。

同じ理由で、**復元ボタンはストアが応答しない状態でも常に表示してください**。別端末で購入した人にとって唯一の経路であり、しかもそういう時ほど起動時の問い合わせが失敗しています。Appleの要件でもあります。
:::

### 課金ステータスを判定する

ユーザーが有料会員かどうかを判定するカスタムフック（`useSubscription`）を作ります。

```typescript
// hooks/useSubscription.ts
import { useState, useEffect } from 'react';
import Purchases from 'react-native-purchases';

export function useSubscription() {
  const [isPro, setIsPro] = useState(false);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    const checkProStatus = async () => {
      try {
        const customerInfo = await Purchases.getCustomerInfo();
        setIsPro(customerInfo.entitlements.active['pro'] !== undefined);
      } catch (e) {
        setIsPro(false);
      } finally {
        setLoading(false);
      }
    };

    checkProStatus();

    // 課金ステータスの変更（解約・購入・更新）をリアルタイム監視
    Purchases.addCustomerInfoUpdateListener((info) => {
      setIsPro(info.entitlements.active['pro'] !== undefined);
    });
  }, []);

  return { isPro, loading };
}
```

アプリ内の各所で `const { isPro } = useSubscription();` を呼び出し、`!isPro` の場合は「習慣の登録上限を3個まで」に制限したり、広告を表示したりするロジックを組み込みます。

**広告の分岐は「表示しない」ではなく「要求しない」位置に置いてください**。権利があれば広告のリクエスト自体が起きない形にしておくと、課金したユーザーの端末で一瞬だけ広告枠が見える、といったことがなくなります。

### 無料トライアルとプロモーションコード

初期のユーザー獲得には「最初の2週間無料トライアル」が絶大な威力を発揮します。

StoreKitおよびGoogle Play Console側で「無料試用（Free Trial）」を設定しておくだけで、RevenueCatの購入フローが自動的に「トライアル付き購入」として処理してくれます。リスクなく課金体験を試してもらうことで、有料転換率を最大化できます。

## 5. 課金機能の必須審査要件と審査用メモの書き方

### ペイウォールに必須の4要素

アプリ内課金（広告削除やサブスクリプション）を導入する場合、Appleのガイドライン（Guideline 3.1.1）により、購入画面に以下の要素が**視覚的に明記されていること**が絶対条件です。

1. **購入の復元（Restore Purchases）ボタン**: 端末変更時や再インストール時に再課金させないためのボタン。タップ時に復元処理が走る必要があります。
2. **利用規約（Terms of Service / EULA）へのリンク**: タップすると規約ページが開くこと。
3. **プライバシーポリシー（Privacy Policy）へのリンク**: タップするとポリシーページが開くこと。
4. **サブスクリプション期間と価格**: 例「月額350円・いつでも解約可能」

これらが欠けていると**ほぼ確実にリジェクトされる**ため、購入コンポーネント内に必ず目立つ形で配置しておきます。前節のコードは、この4つを最初から含んだ形になっています。

:::caution[免責事項はEULAの代わりになりません]
プライバシーポリシーと免責事項の2本を用意していても、**サブスクを入れるとAppleは利用規約（EULA）への機能するリンクを、アプリ内とApp Store Connectの両方に要求します**。3本目が必要になる、と覚えておいてください。

なお日本では、**消費者契約法8条により事業者の責任を全部免除する条項は無効**です。「当社は一切の責任を負いません」は書いても効きません。有効なのは「軽過失による損害については、お客様が過去1か月に支払った利用料金相当額を上限とします」のように**上限を設ける形**です。
:::

### レビュアーに喜ばれる審査用メモの書き方

App Store Connect の審査提出画面には「App Reviewに関する情報（審査用メモ）」欄があります。

ここに親切な案内を英語で書いておくと、レビュアーが迷わずスムーズに承認してくれます。

```text
【審査用メモの記載テンプレート】
Dear App Review Team,

Thank you for taking the time to review HabitFlow.
- This app is an offline-first minimalist habit tracker designed with Expo.
- No login or personal information is required. All data is stored locally via AsyncStorage.
- To test the core features:
  1. Tap the '+' button at the bottom right to add a habit (e.g., "Reading").
  2. Tap the checkbox on the habit card to mark it as completed.
  3. Navigate to the History tab to review the streak calendar.
  4. Navigate to the Settings tab to test data reset.

If you have any questions or need further details, please reach out to:
Email: your-email@example.com
```

:::danger[掲載文と審査メモの「課金はありません」を消し忘れないこと]
課金を追加したのに、説明文や審査メモに「**アプリ内課金はありません**」という以前の記述が残っていると、それは単なる古い文章ではなく**メタデータ不一致としてリジェクトの直接の理由になります**。

課金を足したら、必ず掲載文と審査メモを読み直してください。ここは実装より先に古くなる場所です。
:::

## 6. 審査提出とリジェクトされたときの対応

### 提出とステータスの推移

すべての項目に緑のチェックがついたら、**「審査に追加」** → **「審査に提出」** をクリックします。

1. **Waiting for Review（審査待ち）**: 通常数時間〜24時間程度。
2. **In Review（審査中）**: レビュアーが実際に操作中（1〜3時間程度）。
3. **Pending Developer Release（公開待ち）** または **Ready for Sale（販売中）**: **祝・合格！** ストアに並びます。

### もしリジェクトされたら

「Guideline XX.X に抵触したため却下されました」という通知が届いても、落ち込む必要は全くありません。**リジェクトはアプリ開発の日常茶飯事**です。

レビュアーから送られてきたメッセージをそのままAIエージェントに貼り付けます。

```text
【プロンプト】
Appleの審査チームから以下のリジェクト理由が届きました。
ガイドラインの意図を解説し、現在のコードのどこを修正すれば合格できるか具体的なコード修正案を提示してください。
また、レビュアーへの丁寧な返信メッセージのドラフト（英語）を作成してください。

[レビュアーからのメッセージ本文]
```

### レビュアーへの返信英文テンプレート

```text
Dear App Review Team,

Thank you for your feedback regarding Guideline [ガイドライン番号].
We have updated the app in build [新しいビルド番号] to resolve this issue:
- [修正点1: e.g., Added a clear "Restore Purchases" button to the paywall view.]
- [修正点2: e.g., Updated privacy links in accordance with the guideline.]

Please review the updated build. Thank you for your support!
```

指摘された箇所をAIと一緒に数十分で直し、新しいビルド番号で再提出すれば、大半は次回ですんなり通過します。

## 7. 公開とマネタイズ編の総まとめと次のフェーズへの橋渡し
